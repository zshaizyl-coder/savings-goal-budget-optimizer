# 需求草案

> 本文档保留阶段 0 的需求骨架。真实微信账单 EDA 已完成，冻结范围以 `requirements-v1.md` 为准。

## 角色与边界

- 主要角色：管理个人账单与储蓄目标的用户。
- 分析边界：通用算法框架，每个用户独立估计参数。
- 数据边界：真实账单只在本地私有目录中处理；测试使用脱敏或模拟数据。

## 候选核心流程

1. 导入并识别账单来源。
2. 清洗、去重并标准化交易。
3. 标记消费、收入、退款、转账及其他特殊交易。
4. 生成日度、周度和月度汇总。
5. 估计个人短期消费并评价预测误差。
6. 判断储蓄目标是否可行。
7. 在约束下生成分类预算。
8. 录入实际消费或状态变化后滚动再规划未来预算。
9. 在 Web 页面展示数据质量、预测、预算和储蓄进度。

## 关键业务规则待确认

- 周定义及首尾不完整周处理。
- 退款、撤销和内部转账的配对规则。
- 消费类别映射与用户纠错流程。
- 固定支出、最低必要支出与可调整支出的用户确认机制。
- 跨月周预测到自然月的分摊规则。
- 不可行目标的建议优先级和用户偏好解释。

## 验收原则

- 每个统计数字可追溯到代码和输入数据版本。
- 不泄露真实交易对象、姓名、账号和备注。
- 预测使用遵守时间顺序的滚动验证，不随机打乱时间序列。
- 不可行目标不输出伪可行预算。
- 再规划不修改已发生历史交易。
