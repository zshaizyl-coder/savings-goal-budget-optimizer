# Web系统设计与核心算法集成

## 1. 目标与边界

阶段9把阶段4—8已验证能力包装成可操作的本地Web系统，不改变预测、可行性、优化和再规划公式。前端只负责录入、展示和确认；所有统计口径、阈值与金额计算由后端完成。

架构：`Vue 3 → FastAPI Router → WebFinanceService适配器 → 阶段4—8服务 → SQLAlchemy → SQLite`。Router只做验证、鉴权和DTO转换，不包含数学优化。

## 2. 页面与用户流程

| 页面 | 用户问题 | 后端能力 |
| --- | --- | --- |
| 登录 | 如何进入自己的数据空间 | PBKDF2密码哈希、签名访问令牌 |
| 首页 | 当前目标和消费状态如何 | Dashboard聚合 |
| 账单 | 导入是否成功、交易如何分类 | 微信导入、ImportBatch、Transaction、人工分类 |
| 消费分析 | 最近花费趋势如何 | 阶段5统一日/周/月口径 |
| 周度预测 | 正常消费参考是多少 | 阶段6选定模型类型、最新历史重估 |
| 储蓄目标 | 目标、收入和生活约束是什么 | Snapshot、Goal、Income、Constraint |
| 预算计划 | 目标是否可行、各类如何调整 | 阶段7可行性和个性化优化 |
| 动态调整 | 冲击后如何恢复 | 阶段8事件、预览、确认式replan |
| 历史方案 | 为什么预算发生变化 | parent_plan版本链和只读明细 |

完整流程已通过API端到端测试：注册登录 → 导入完全模拟账单 → 分析 → 目标/约束 → 预测 → 预算候选 → 用户激活 → 计划外支出 → replan预览 → 用户确认 → Plan v1/v2历史。

## 3. 关键交互规则

- 目标不可行返回HTTP 200和 `feasible=false`，页面展示最高目标、收入缺口和建议日期，不称为系统错误。
- 预算候选先保存为 `DRAFT`；只有用户点击确认后成为 `ACTIVE`。
- 突发事件不会自动替换预算。预览不写计划，确认接口才通过单一数据库事务切换版本。
- ABC只表示OTHER审核优先级，不表示风险、消费必要性或可削减性。
- LOW/MEDIUM/HIGH是情景风险，不展示为成功概率。
- 餐饮显示“中等置信参考”，购物显示“低置信参考”。
- 金额API统一使用整数分；Vue只通过 `formatMoney` 展示人民币元。

## 4. 认证与数据隔离

密码采用PBKDF2-SHA256和独立随机盐保存。访问令牌使用服务端密钥进行HMAC签名并包含到期时间。V1不实现OAuth、刷新令牌、设备管理或RBAC。

所有交易、目标、计划、事件查询都以令牌解析出的 `user_id` 过滤；客户端不能通过请求体指定其他用户。自动化测试验证用户B不能查看或修改用户A交易。

## 5. 上传与隐私

- 仅接受 `.xlsx`，检查ZIP文件签名和可配置大小上限。
- 不信任原始文件名；使用随机临时文件，导入完成后立即删除。
- 不保存真实本地路径、完整商户、账号、备注或原始交易号。
- 导入完成时可在 `data/private/` 生成按用户隔离的临时分类审核队列；只保留脱敏短文本和代表交易ID，Git忽略。登录用户确认后按匿名商户指纹批量更新，私有短文本不进入主数据库、日志或API审计表。
- 测试、Demo和前端只使用 `wechat_bill_demo.xlsx` 完全模拟账单。
- 错误响应只提供业务码、可理解文案和请求ID，不向前端返回Python、SLSQP或SQLAlchemy异常。

## 6. 空态、加载与刷新

无账单、目标、预测或计划时，页面提供下一步入口而非显示误导性的0。上传、预测、预算和replan有loading及成功/失败反馈。令牌保存在浏览器本地存储，所有业务资源保存在SQLite，因此刷新页面不会丢失计划。

## 7. 测试与性能

- 后端新增14项API测试，覆盖认证、上传、分析、分类、预测、可行/不可行预算、执行偏差、事件、replan、历史和用户隔离。
- 前端9项Vitest覆盖整数分/百分比格式化、精确元转分、API安全错误映射、上传超时提示和目标表单边界。
- 两条端到端业务流程使用一年完全模拟账单实际运行。
- 本地浏览器冒烟检查确认登录、Dashboard空态、账单导入、导入历史、OTHER审核队列和交易表可正常渲染，控制台无错误。
- 2445条完全模拟交易的单机冒烟测试：分析约46.91ms、预算优化约44.08ms、滚动再规划约131.29ms。结果位于 `experiments/web/performance.json`，只说明本机交互性能，不代表并发基准。

## 8. 页面截图说明

答辩截图应使用完全模拟账号和账单，建议截取：Dashboard目标卡片与周趋势、消费分析四图、预算自然消费/推荐预算对比、不可行目标建议、replan旧/新方案差异、版本时间线。截图不得出现真实商户、姓名、账号或真实数据库内容。

## 9. 当前限制

- 支付宝和银行卡解析尚未实现，页面明确标记未开放。
- 导入报告中的未分类比例是“自动规则处理后的导入时覆盖率”；人工确认后的当前OTHER比例由审核接口实时重算，两者不能混为模型准确率。
- 当前是单机SQLite部署，适合个人或少量用户，不面向高并发。
- 签名令牌为本科项目的简单认证方案，不包含企业级会话撤销。
- 目标金额、目标日期和预算约束变化可记录为审计事件，但V1要求用户先在目标页保存新输入；不会仅凭事件说明文本自动改写财务约束。
- Element Plus主包仍有约1.08 MB的构建警告；页面已懒加载，ECharts按需注册后图表块由约1.13 MB降至约0.56 MB。当前不影响单机交互，但部署优化时可继续拆分组件。
