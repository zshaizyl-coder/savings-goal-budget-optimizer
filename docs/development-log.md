### 阶段 3：技术架构与数据库设计

- Git 起点：工作区干净；当前分支 `feature/system-architecture` 与 `main` 同指向 `6982484`；`v0.1-planning-baseline` 存在；没有真实 Excel 被跟踪。
- 依据：重新读取真实 EDA、V1 需求、既有架构、数据库、算法和开发日志，没有仅依赖对话记忆。
- 架构：确定模块化单体，分为 Vue 展示、FastAPI 适配、业务服务、分析/预测/优化/再规划、仓储和 SQLite；账单解析与清洗为独立导入链。
- 技术栈：SQLite + SQLAlchemy 2.x + Alembic；Pandas/NumPy 用于导入分析；statsmodels、scikit-learn 和 SciPy 后续按实验引入；CVXPY 不作为默认依赖。
- 金额：交易、收入、预算、约束和储蓄统一使用整数分；源金额用 Decimal 转换；API 禁止浮点金额。
- 时间：存储 UTC，用户时区默认 Asia/Shanghai；所有模块统一周一至周日；交易表不冗余 week_number/month。
- 数据模型：统一 Transaction 支持微信、支付宝和银行卡；资金流方向与语义分离；退款为独立交易；跨源重复和内部转账使用候选链接与人工决议。
- 隐私：不长期保存真实交易对象、账号、银行卡号、详细备注和完整文件路径；幂等和匹配使用不可逆指纹。
- 规划：当前存款独立为财务快照；目标引用基准快照；预算计划保留版本、父计划和触发事件；不可行计划保存诊断但不生成假明细。
- API：新增导入、交易确认、分析、预测、目标、约束、预算、事件和再规划接口草案；业务不可行返回 `feasible=false`，不是 HTTP 异常。
- 代码骨架：只创建框架无关领域契约、预测/优化/仓储协议和目录边界，没有实现解析器、模型、优化算法或 Web 页面。
- 测试：原有 3 项 EDA 测试与新增 9 项结构验证共 12 项全部通过；Python 编译检查通过。
- 发现的问题：完全不保存商户文本能降低隐私风险，但可能降低逐笔分类纠错的可辨识度。V1 先用日期、金额、来源和脱敏类型；若可用性测试证明确有需要，再评估用户自愿开启、加密且可删除的短标签。
- 需求影响：没有修改 `requirements-v1.md`；阶段 3 只将其落实为可扩展结构和接口。

### 阶段 5：消费行为分析与预测数据集构建

- Git 起点：`main` 干净，阶段 4 三个提交已合并；只有 `v0.1-planning-baseline`，真实账单、私有 SQLite 和上传路径均未被跟踪；创建 `feature/consumption-analysis`。
- 统一口径：建立唯一事实表；消费支出计毛额，消费退款负向冲减；转账、余额转移、红包、收入候选和其他特殊流不进入核心消费。`transaction_count` 表示全部标准交易，另设消费和退款计数。
- 连续数据：从 2,445 条标准 Transaction 生成 366 个连续日、53 个观测周（51 个完整周）和 13 个月；零日、零周、空月均可补零并已有测试。
- 阶段 1 对账：13 个月毛额、退款、净额逐月最大差 0；完整周 51、异常周 4，关键周统计一致。Q1 的 0.01 元显示差来自半分插值和舍入。类别差来自可靠退款回冲及统一类别拆分，已在报告说明。
- 退款敏感性：两种方案的总消费完全相同；29 条可靠退款回冲类别，74 条未确认退款保留为 `unallocated_refund`。未分配金额 965.76 元，占退款金额 31.4%。
- 类别质量：OTHER 1,044 笔，占消费笔数 71.0%、毛额 49.9%，51 周均活跃、CV 0.98，但因语义异质判为 C；餐饮和购物满足透明 A 类规则，其余类别为 B/C，不进入正式类别预测。
- 时间规律：完整周均值 755.40 元、中位数 508.90 元、标准差 1,091.12 元、CV 1.44、偏度 5.09；IQR 识别 4 个高异常周。周末日均净消费是工作日 1.48 倍，但消费频次略低，不能解释成所有类别都增加。
- 大额规则：消费金额 95% 分位数 73.99 元，IQR 上界 47.75 元；默认使用较大值 73.99 元并允许用户覆盖。统计异常不自动等同计划外消费。
- 数据集：冻结 `weekly-forecast-v1`；总量、餐饮、购物均由同一生成器产生，lag/rolling 全部先 shift(1)。未加入 previous_month_mean，避免 51 周样本上的弱特征膨胀。
- 图表与产物：生成日/周/月及类别脱敏 CSV、质量与敏感性表、6 张白底论文图；未导出事实表或任何交易对象、商户、账号和备注。
- 测试：新增 22 项阶段 5 测试（含用户类别覆盖的数据库集成验证）；全仓 52 项测试、Python 编译检查、真实数据重建和隐私扫描均通过。
