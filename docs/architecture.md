# 系统架构草案

## 设计状态

本文件仅定义阶段 0 的模块边界。技术细节将在真实数据结构验证后逐步确定。

## 候选分层

```text
Vue 3 Web
    ↓ HTTP/JSON
FastAPI 应用层
    ├─ 导入与校验服务
    ├─ 分析与预测服务
    ├─ 目标可行性服务
    ├─ 可插拔预算策略服务
    └─ 滚动再规划服务
    ↓
领域模型与数据访问层
    ↓
SQLite + 本地私有文件存储
```

## 模块原则

- 每种账单来源实现独立解析适配器，输出统一交易模式。
- 原始数据、标准化数据、聚合特征和模型结果分层存储并保留血缘信息。
- 预测器与预算策略使用统一接口，避免写死单一算法。
- 统一比例削减、历史占比分配和个性化优化作为并列策略实现。
- 固定预算与滚动优化共享同一评价接口。
- 已发生交易不可由规划模块修改。
- Web 层不直接实现分析或优化算法。

## 隐私与可追溯性

- 私有上传文件不进入 Git。
- 默认日志只记录任务状态、行数和匿名错误，不记录交易对象或备注。
- 每次导入记录来源类型、文件指纹、导入时间和解析器版本，用于去重与复现。
- 研究报告只输出聚合统计，类别稀疏时避免可识别披露。

## 待真实数据验证

- 已验证微信导出包含 17 行说明、位于第 18 行的表头和 11 个标准字段；解析器不得假定首行即表头。
- 已验证状态字段会把具体退款金额写入状态文本，标准化层需要按模式归一化并保留原值引用。
- 已验证微信缺少可靠生活类别；分类服务需要区分“系统建议”和“用户确认”，并保留纠错记录。
- 已验证 51 个完整周无零消费周但波动较高；预测服务以总量短期滚动预测为主。
- 后台任务是否异步化仍待 Web 阶段性能测试；V1 默认同步或轻量后台任务。
